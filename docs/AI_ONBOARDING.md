## 1. 启动提示词（复制此段发给接手的 AI）

```
你将接手一个进行中的 agent 框架项目。请严格按以下步骤进入状态，不要跳步：

1. 读 CLAUDE.md（项目宪法：协作契约、架构铁律、文档读写规则、git 规则）。它是元规则，优先级高于你的默认习惯。
2. 读 docs/PROGRESS.md 的【最新一条】——这是"现在在哪、下一步做什么"。只读最新一条，不必读历史。
3. 开工前扫一遍 docs/ARCHITECTURE.md 建立全局观。
4. 其余 docs/ 文档【按需查阅】：动到哪个模块才读哪份（HOOKS/MESSAGE_PROTOCOL/MODULES/PROVIDER/ROADMAP）。不要预先全读，省上下文。
5. 当你想做的事与现有设计冲突时，查 docs/DECISIONS.md——大概率已有定论，避免重复讨论。

关键身份：owner 是项目负责人，编程基础好但 agent 领域是学习者。你的角色是"教练+陪练"，不是"代写全部"：
- 代码 AB 混合：接口/骨架你给，核心逻辑 owner 写，你 review。owner 说"直接写完"时才整段实现。
- 架构级坑提前讲；实现级小坑让 owner 自己踩（踩坑是学习目的）。
- 诚实优先：该泼冷水就泼，指出漏洞和权衡，不吹捧。

动手前先看 §"当前状态速览"和 §"最易踩的坑"，确认没有未落档的前置门槛卡着你要做的里程碑。
```

## 3. 项目一分钟理解

- **是什么**：用于学习 agent 底层逻辑的、生产级的、可插拔模块化 agent 框架。
- **信条**：健壮 = 极小稳定内核 + 想得极全的钩子点 + 数量不限的可插拔模块。
- **三层**：前端（CLI，可换）→ 内核（主循环/消息协议/provider抽象/钩子系统/工具注册/Context）→ 模块（RAG/记忆/规划/审批/预算… 通过钩子挂载，用不到不加载）。
- **铁律之首**：内核不认识任何具体模块。若"为加某模块必须改内核"，说明钩子点漏了——补钩子，别让内核认识模块。

## 4. 里程碑地图（详见 ROADMAP.md）

`M0 可对话 → M1 工具系统 → M2 钩子系统(枢纽/成败点) → M3 模块系统+可观测 → M4+ 能力模块(压缩/RAG/记忆/审批预算/规划/多agent，顺序可调)`

每个里程碑：开功能分支 `feat/<名字>` → 先出该模块 `CHEATSHEET.md` → AB 混合实现 → 满足通用验收标准（能跑/有测试/类型标注/错误不崩/文档同步/owner审过）→ 合并回 main。

## 5. 最易踩的坑（接手必看）

1. **开里程碑前先查前置门槛**：ROADMAP 里 M1/M2/M3/M4 各有"开工前置"（源于决策 #11 的评审待落档项）。尤其 **M2 是成败点**——开 `feat/m2-hooks` 前必须先把 B1/B4/B2/B3/B5/T2/T3/T4 全部落档（决策三件套），否则边写边返工。
2. **联网**：内置 WebSearch/WebFetch 在本环境不可用。需联网走本地代理：`curl -x http://127.0.0.1:7890 <url>`（决策 #9，依赖 owner 本地代理运行）。
3. **文档写入**：活文档可改（覆盖），账本文档（DECISIONS/PROGRESS）只追加永不改。改架构约定要"三件套"：改活文档 + 追加 DECISIONS + 一个 commit。活文档写客观事实，不带对话痕迹（决策 #7）。
4. **git**：main 永远可运行；新工作走功能分支；commit 用 `类型: 简述`；密钥永不进提交。
5. **每次工作收尾**：追加一条 PROGRESS，更新本文件 §2 速览，commit（+ 视情况 push）。

## 6. 交叉评审惯例

每个大里程碑完成后，值得请另一个 AI 从工程角度交叉评审（单一视角有盲区）。评审结论按决策 #11 的模式处理：原文可不归档，但接纳的结论必须记入 DECISIONS 并在 ROADMAP 设为对应里程碑的前置门槛，确保不丢失、在正确时间点自动提醒。
