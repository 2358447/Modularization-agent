## #1 · 2026-07-30 · 内核采用同步（synchronous）实现，而非 async

**背景**：内核主循环、provider 调用、工具执行的执行模型需在动第一行代码前确定，因为它渗透内核每一行，后期改动成本极高。

**决策**：内核用**同步**代码实现。

**理由**：
- 项目首要目标是**看清 agent 底层逻辑**，同步代码调用栈清晰、debug 直接，最利于学习。
- owner 时间充足、不赶工，无需为并发性能提前买单。
- 并行工具调用、流式输出等需要并发的能力，等真正需要时再用线程/进程或局部重构引入，并把"同步→异步重构"本身当作一节学习课。

**影响**：
- provider 接口、主循环、钩子回调、工具执行签名全部为同步。
- 流式输出初期用同步生成器（generator）实现即可满足 CLI 实时显示。

**状态**：生效。
