## 1. 模块统一模板（外壳契约）

所有模块共享同一外壳，差异只在内部逻辑——这是"可插拔"的前提：内核用统一方式加载、触发、卸载任何模块，无需认识其内部。

### 1.1 一个模块声明什么

```
Module
├─ name          : 唯一模块名（也是 metadata 命名空间，见 MESSAGE_PROTOCOL §5）
├─ hooks         : 监听哪些钩子点，各自的回调、优先级、角色（观察者/拦截者）
├─ tools         : 向工具注册表贡献的工具（可无）
├─ dependencies  : 依赖的其他模块或后端（可无；缺失时的降级见 §2.3）
├─ setup()       : 加载时初始化（建连接、载资源）
└─ teardown()    : 卸载时清理（关连接、落盘）
```

### 1.2 钩子回调的统一签名

```
callback(ctx: Context) -> HookResult | None      # 同步（决策 #1）
```
- 观察者：读 `ctx`，返回 `None`。
- 拦截者：返回 `HookResult`（修改指令 / SKIP / HALT / REPLACE / 错误处置建议，见 HOOKS §3）。
- 回调**只通过 `ctx` 读写数据**（铁律 5），不接收其他入参、不私自访问别的模块。

### 1.3 数据交互只走 Context

- 模块间、模块与内核间的一切数据交互只经 `Context`（历史、可用工具、运行元数据、模块共享区）。
- 模块在消息上附加的旁路信息写入该消息 `metadata[本模块name]`（命名空间隔离）。
- 模块自身的跨钩子状态存入 `ctx` 模块共享区中以自己 name 为键的格子。
- **禁止**：直接 import 另一模块并调用其内部；绕过钩子改主循环。

## 2. 模块加载与生命周期

- **启用声明**：由配置（`config/`）声明本次运行启用哪些模块；未启用的完全不加载，零成本。
- **加载顺序**：内核按依赖关系拓扑排序后依次 `setup()`；循环依赖报错拒绝启动。加载失败的模块标记为未启用并降级，不阻断其他模块（除非它被硬依赖）。
- **优雅降级**（铁律 3）：`dependencies` 缺失时模块应能降级（受限功能运行或自我禁用并记 trace），不得导致整体崩溃。运行期钩子回调崩溃由 HOOKS §5 四道防线兜底。
- **卸载**：按加载逆序 `teardown()`。

**setup/teardown 绑框架生命周期，而非 run 生命周期**：`setup()` 框架启动时执行一次，`teardown()` 框架关闭时执行一次，二者跨所有 run 存活（长期记忆/存储后端的连接不应每个 run 关闭重建）。模块若要在每个 run 边界做事（会话记忆加载/落盘），用 `on_run_start`/`on_run_end` 钩子，不要用 setup/teardown。

## 3. 拦截者执行顺序

同一钩子点多个拦截者时按优先级排序执行。

### 3.1 顺序为何关键

以 `before_model_call` 为例，挂着 RAG、记忆注入、上下文压缩：正确顺序必须是**先注入（RAG/记忆把内容加进历史）→ 再压缩（对含注入内容的完整历史裁剪）**。若压缩先跑，它压的是还没注入的历史，随后注入的新内容逃过压缩、可能撑爆窗口。因此**注入类优先级 < 压缩类**。

### 3.2 优先级方案（设想）

> 以下分段是设计设想，供实现参考。**模块少时用显式有序列表即可**；等真正出现多个冲突模块时再引入分段。确切数字在各模块实现时登记进 §5。

用分段预留区间，便于未来插入而不重排：

| 区间 | 语义 | 典型模块 |
|------|------|---------|
| 0–99 | 最先：准备/加载类 | 会话记忆加载、预算初始化 |
| 100–199 | 内容注入类 | RAG 注入、长期记忆注入 |
| 200–299 | 内容加工/压缩类（须在注入之后） | 上下文压缩、prompt 加工 |
| 300–399 | 校验/拦截类 | 审批、预算拦截、参数校验、限流 |
| 400–499 | 缓存/替换类 | 响应缓存、工具结果缓存（REPLACE） |
| 900+ | 最后：观察/记录类 | 可观测 |

**缓存类位置**：工具结果缓存挂 `before_tool_call`，命中则 REPLACE。依短路规则（HOOKS §D），缓存排在审批**之后**（审批@300 / 缓存@400）：审批拒绝（SKIP）会短路，被拒的调用自然不查缓存。

## 4. 模块总目录

覆盖已想到的能力，体现"覆盖面尽量广"。每项标注主要钩子点、角色、贡献工具、依赖、状态（当前均为 `规划中`）。实现按 ROADMAP 顺序逐个推进，非一次全做。

### 4.1 上下文与知识

| 模块 | 主要钩子 | 角色 | 贡献工具 | 依赖 |
|------|---------|------|---------|------|
| RAG（检索增强） | before_model_call | 拦截(注入) | 可选：手动检索工具 | 向量库/嵌入模型 |
| 上下文压缩 | before_model_call | 拦截(压缩) | — | provider(可能调 LLM 摘要) |
| 长期记忆 | before_model_call, on_iteration_end, on_run_end | 拦截(注入)+观察 | — | 存储后端 |
| 短期记忆/会话 | on_run_start, on_run_end | 拦截+观察 | — | 存储后端 |

### 4.2 控制与安全

| 模块 | 主要钩子 | 角色 | 依赖 |
|------|---------|------|------|
| 审批（人工确认） | before_tool_call | 拦截(SKIP/HALT) | 前端交互 |
| 预算控制 | on_run_start, after_model_call, before_tool_call | 观察+拦截(HALT) | provider 用量 |
| 限流 | before_tool_call, before_model_call | 拦截 | — |
| 参数校验（增强） | before_tool_call | 拦截 | 工具 schema |
| 死循环检测 | on_iteration_start | 拦截(HALT) | — |

### 4.3 可靠性

| 模块 | 主要钩子 | 角色 | 依赖 |
|------|---------|------|------|
| 重试 | on_tool_error, on_error | 拦截(处置建议) | — |
| 错误恢复/降级 | on_error | 拦截(处置建议) | — |
| 响应缓存 | before_model_call, after_model_call | 拦截(REPLACE) | 缓存后端 |
| 工具结果缓存 | before_tool_call, after_tool_call | 拦截(REPLACE) | 缓存后端 |

> **响应缓存落地机制**：命中时在 `before_model_call` 返回 `REPLACE(替代 assistant 响应)`，内核跳过 `provider.chat`（HOOKS §D）。这是"调用前短路"，流式与非流式下均正确；`after_model_call` 仅用于非流式下事后写缓存/观察，流式下退化为纯观察者（HOOKS §4.1）。

### 4.4 认知增强

| 模块 | 主要钩子 | 角色 | 贡献工具 | 依赖 |
|------|---------|------|---------|------|
| 规划/任务分解 | on_run_start, before_model_call | 拦截 | 可能贡献"计划"工具 | provider |
| 反思/自我批判 | on_iteration_end | 拦截 | — | provider |
| 多 agent 协作 | 多钩子 | 拦截+观察 | agent-as-tool | 内核可嵌套 |

### 4.5 可观测与运维

| 模块 | 主要钩子 | 角色 | 依赖 |
|------|---------|------|------|
| 可观测/Trace 展示 | 全部钩子 | 观察 | 内核事件流(HOOKS §6) |
| 成本统计 | after_model_call, on_run_end | 观察 | provider 用量 |
| 会话持久化 | on_run_start, on_run_end | 观察+拦截 | 存储后端 |

> 目录可持续增补。新增模块登记于此并在 §5 登记优先级。
