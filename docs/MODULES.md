## 1. 模块统一模板（外壳契约）

所有模块共享同一外壳，差异只在内部逻辑。这是"可插拔"的前提——内核用统一方式加载、触发、卸载任何模块，无需认识其内部。

### 1.1 一个模块必须声明什么

```
Module
├─ name          : 唯一模块名（也是 metadata 命名空间，见 MESSAGE_PROTOCOL §5）
├─ hooks         : 该模块监听哪些钩子点，各自的回调、优先级、角色（观察者/拦截者）
├─ tools         : 该模块向工具注册表贡献的工具（可无）
├─ dependencies  : 依赖的其他模块或后端（可无；缺失时的降级行为见 §2.3）
├─ setup()       : 加载时初始化（建连接、载资源）
└─ teardown()    : 卸载时清理（关连接、落盘）
```

### 1.2 钩子回调的统一签名

```
callback(ctx: Context) -> HookResult | None      # 同步（决策 #1）
```
- 观察者：读 `ctx`，返回 `None`。
- 拦截者：返回 `HookResult`（修改指令 / SKIP / HALT / REPLACE / 错误处置建议，见 HOOKS §3）。
- 回调**只通过 `ctx` 读写数据**（铁律 5），不接收其他入参、不私自访问别的模块。

### 1.3 数据交互只走 Context

- 模块间、模块与内核间的一切数据交互，只经 `Context`（历史、可用工具、运行元数据、模块共享区）。
- 模块在消息上附加的旁路信息，写入该消息 `metadata[本模块name]`（命名空间隔离）。
- 模块自身的跨钩子状态，存入 `ctx` 的模块共享区中以自己 name 为键的格子。
- **禁止**：模块直接 import 另一模块并调用其内部；禁止绕过钩子改主循环。

## 2. 模块加载与生命周期

### 2.1 启用声明
- 由配置（`config/`）声明本次运行启用哪些模块（呼应"用不到可隐藏"）。
- 未启用的模块完全不加载，零成本、零钩子监听。

### 2.2 加载顺序
- 内核按依赖关系拓扑排序后依次 `setup()`；有循环依赖则报错拒绝启动。
- 加载阶段的失败（如 `setup()` 抛错）：记录并按策略处理——该模块标记为未启用并降级，不阻断其他模块（除非它是被硬依赖的）。

### 2.3 优雅降级（铁律 3 的运行时体现）
- 模块声明的 `dependencies` 缺失时，模块应能降级：要么以受限功能运行，要么自我禁用并记 trace，**不得导致整体崩溃**。
- 运行期该模块的钩子回调崩溃，由 HOOKS §5 四道防线兜底（观察者零影响、拦截者当未发生）。

### 2.4 卸载
- run 结束或框架关闭时按加载逆序 `teardown()`。

## 3. 全局优先级表（拦截者顺序）

同一钩子点多个拦截者时按优先级排序执行。**约定：数字小者先执行**（升序）。观察者顺序无关但仍登记以保证可复现。

### 3.1 顺序为何关键（推演）

以 `before_model_call` 为例，挂着 RAG、长期记忆注入、上下文压缩三个拦截者。正确顺序必须是：

```
先注入（RAG、记忆把内容加进历史） → 再压缩（对含注入内容的完整历史做裁剪）
```

若压缩先跑，它压的是还没注入的历史，随后 RAG/记忆注入的新内容逃过压缩，可能撑爆上下文窗口——压缩形同虚设。因此：**注入类优先级数字 < 压缩类**。

### 3.2 优先级分段约定

用分段预留区间，便于未来插入而不重排：

| 区间 | 语义 | 典型模块 |
|------|------|---------|
| 0–99 | 最先执行：准备/加载类 | 会话记忆加载、预算初始化 |
| 100–199 | 内容注入类 | RAG 注入、长期记忆注入 |
| 200–299 | 内容加工/压缩类（须在注入之后） | 上下文压缩、prompt 加工 |
| 300–399 | 校验/拦截类 | 审批、预算拦截、参数校验、限流 |
| 400–499 | 缓存/替换类 | 响应缓存、工具结果缓存（REPLACE） |
| 900+ | 最后执行：观察/记录类 | 可观测（虽为观察者，排末尾） |

> 具体每个模块的确切数字，在该模块实现时登记进 §5 的优先级登记表，并随实现更新。

### 3.3 缓存类的位置说明
- 工具结果缓存挂 `before_tool_call`，若命中则 REPLACE（HOOKS §D），跳过真实执行。它应在审批之后（被拒的调用不必查缓存）还是之前，属模块实现时的具体权衡，登记时注明理由。
