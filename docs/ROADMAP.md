## 0. 两条总原则

1. **图纸一次画完，砖一块一块砌**：设计文档已提供全局视野；实现严格分里程碑，一次只做一个，做完可运行、可验收再进下一个。
2. **可讲述性**：里程碑顺序即"由简入繁的学习路径"，git 合并点即章节里程碑，也为将来开源当教程预留叙事骨架。

## 1. 通用验收标准（每个里程碑都适用）

- [ ] **能跑**：`examples/` 下有 demo 脚本可手动运行并展示本里程碑能力。
- [ ] **有测试**：核心逻辑有单元测试，覆盖正常路径 + 至少一个错误路径。
- [ ] **类型标注**：公开接口有 type hints。
- [ ] **错误不崩**：异常被捕获并合理处理（能喂回模型的喂回，该降级的降级）。
- [ ] **文档同步**：涉及的活文档已更新（含"待实现阶段敲定"项的落定）；重大决策入 DECISIONS。
- [ ] **owner 审阅通过** + **合并回 main**（main 保持可运行）。

## 2. 里程碑序列

> 每个里程碑一个功能分支，先产出该模块的 `CHEATSHEET.md`（决策 #4）。

### M0 · 最小内核骨架（可对话）★第一个★
**分支**：`feat/m0-kernel-skeleton`
**目标**：打通"用户说话 → OpenAI 兼容模型响应 → CLI 显示"的最小闭环，**暂不含工具、不含钩子模块**。
**范围**：Message 结构（text 块最小实现）+ Provider 抽象 + OpenAI 兼容 `chat`（决策 #9）+ 极简主循环（纯对话）+ 极简 CLI + Context 雏形 + 内核持有 system prompt（MESSAGE_PROTOCOL §1.1）+ CLI 捕获 Ctrl-C 优雅退出。
**验收补充**：CLI 里多轮对话跑通。
**已知限制**：M4 压缩模块前不处理上下文溢出——超窗口直接由 provider 报错。
**学习点**：消息协议、provider 抽象、主循环骨架。
**准备**：owner 备好 OpenAI 兼容 key + base_url，入 `.env`。

### M1 · 工具系统
**分支**：`feat/m1-tools`
**目标**：模型能调用工具并拿到结果继续（ReAct 闭环）。
**范围**：Tool Registry（注册、schema 生成、参数校验、错误捕获）+ 主循环工具分支（解析 tool_call → 执行 → 产出 tool_result → 回灌，一对一粒度）+ 多工具串行处理（HOOKS §C）+ provider 翻译补齐 tool_call/tool_result（→OpenAI）+ 一两个示例工具（计算器、读文件）。`call_id` 透传厂商值（决策 #10）。
**验收补充**：demo 中模型调用工具完成需要外部信息的任务；工具报错时模型收到 is_error 结果并自行调整。
**学习点**：function calling、工具健壮性、错误喂回模型。

### M2 · 钩子系统内核 ★枢纽/成败点★
**分支**：`feat/m2-hooks`
**目标**：落地 HOOKS.md 的钩子机制，为后续所有模块提供挂载点。
**范围**：10 个钩子点在主循环中的广播 + HookResult/ErrorAction 类型 + 观察者/拦截者机制 + 优先级排序 + 拦截者"返回修改指令、内核施加 + 校验"（HOOKS §A）+ 中断三意图 SKIP/HALT/REPLACE（§D）+ 错误裁决 HALT>RETRY>FEED_MODEL（§B）+ 四道防线 + 内核内建结构化事件流。
**注**：HOOKS §7 的机制（逐个施加、短路规则、HALT 补全）是设计设想，实现时验证并回填。
**验收补充**：用一个"空观察者模块"和一个"简单拦截者模块"验证挂载、优先级、崩溃降级、trace 输出。
**学习点**：钩子机制、拦截与降级、可观测事件流。整个架构的枢纽里程碑。

### M3 · 模块系统 + 可观测模块
**分支**：`feat/m3-module-system`
**开工前置**：config 格式敲定（YAML/TOML，声明启用模块 + 优先级覆盖）。
**目标**：落地模块统一模板与加载机制，用"可观测模块"作为第一个真实模块验证。
**范围**：Module 基类/协议、setup/teardown、依赖拓扑排序、优雅降级（MODULES §1/§2）+ 配置声明启用模块 + 模块共享区 + metadata 命名空间隔离的强制 + 可观测模块（消费内核事件流，在 CLI 美化展示每一步）。
**验收补充**：通过配置开关模块观察启用/禁用差异；可观测模块清晰展示思考→工具→结果每一步。
**学习点**：模块加载、可插拔、"看清每一步"落地。

### M4+ · 能力模块（顺序可按需调整）
每个作为独立里程碑与分支，套用通用验收标准。建议顺序（可调，这正是模块化的价值）：
- **M4 上下文压缩**（before_model_call）——最早遇到的真实痛点。前置：PROVIDER 增可选 `count_tokens`。
- **M5 RAG**（before_model_call 注入）——需向量库/嵌入。
- **M6 记忆**（长期/短期）——需存储后端。
- **M7 审批 + 预算**（before_tool_call 拦截）——控制与安全。
- **M8 规划 / 反思**——认知增强。
- **M9 多 agent 协作**——agent-as-tool，内核嵌套。
- **其余**：重试、缓存、限流、死循环检测等，按 MODULES §4 随需求插入。
